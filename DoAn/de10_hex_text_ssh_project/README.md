# DE10-Standard Hardware and HPS Linux Project Guide

This folder contains the board-side hardware and software project for the `DoAnHeThongNhung` SoC Ethernet controller. It starts from a Terasic DE10-Standard reference layout, then exposes six Platform Designer PIO outputs so the HPS Linux side can drive the FPGA seven-segment displays `HEX0` through `HEX5`.

Use this guide when reviewing the actual board project tree behind the public portfolio README.

## Project Scope

| Area | Project-specific evidence |
|---|---|
| Board | Terasic Intel DE10-Standard with Cyclone V SoC |
| Hardware design | Quartus Prime project under `hw/quartus/` |
| Platform Designer system | `hw/quartus/soc_system.qsys` with `pio_hex0` through `pio_hex5` |
| Top-level HDL | `hw/hdl/project.vhd` wires exported PIO signals to `HEX0..HEX5` |
| HPS software path | HPS Linux writes active-low seven-segment values through Lightweight HPS-to-FPGA bridge addresses |
| Review script | `sw/hps/hex_text.sh` writes one six-character payload to the HEX displays |
| Public TCP server path | The repository-level wrappers in `../s1.cpp`, `../s2.cpp`, and `../s3.cpp` generate and start the board-side TCP server |

```text

```

| File | Role |

## Address Map

The PIO addresses are based on the Lightweight HPS-to-FPGA bridge base `0xFF200000`.

| Register | Address | Display |
|---|---:|---|
| `pio_hex0` | `0xFF200040` | `HEX0` |
| `pio_hex1` | `0xFF200050` | `HEX1` |
| `pio_hex2` | `0xFF200060` | `HEX2` |
| `pio_hex3` | `0xFF200070` | `HEX3` |
| `pio_hex4` | `0xFF200080` | `HEX4` |
| `pio_hex5` | `0xFF200090` | `HEX5` |

The project writes the payload left to right on the physical display by mapping the first character to `HEX5` and the sixth character to `HEX0`.

## Hardware Review Steps

1. Open `hw/quartus/project.qpf` in Intel Quartus Prime.
2. Open `hw/quartus/soc_system.qsys` in Platform Designer.
3. Confirm that `pio_hex0` through `pio_hex5` are connected to `hps_0.h2f_lw_axi_master`.
4. Generate HDL if the Platform Designer project has changed.
5. Open `hw/hdl/project.vhd`.
6. Confirm that `pio_hex0_external_export` through `pio_hex5_external_export` are connected to `HEX0` through `HEX5`.
7. Compile the Quartus project when using a full FPGA toolchain environment.
8. Preserve the generated SD-card and boot files only for controlled board bring-up; do not treat them as a generic desktop build target.

## Board-Side Test Steps

After the board is booted into HPS Linux and the FPGA design is loaded:

```sh
cd sw/hps
chmod +x hex_text.sh
./hex_text.sh ABC123
```

Expected review result:

| Check | Expected result |
|---|---|
| Shell output | Six `devmem` writes and an `OK text='ABC123'` line |
| Physical board | `HEX5..HEX0` shows the normalized six-character payload |
| Unsupported characters | Unsupported characters are blanked by the display mapping |

## TCP Server Review Steps

Use the repository-level flow for the public portfolio demo:

1. Copy or run the wrapper flow from the repository-level `DoAn/` folder on the HPS Linux board.
2. Run `s1.cpp` content to create `/tmp/board_tcp_hex_server.py`.
3. Run `s2.cpp` content to create `/tmp/start_board_tcp_hex_server.sh`.
4. Run `s3.cpp` content to start the server.
5. Confirm the board is listening on TCP port `5000`.
6. From the PC client, send a payload such as `HELLO-`, `ABC123`, or `P-0001`.
7. Confirm that the server returns `OK:<payload>` and the physical HEX display updates.

## Safety and Boundaries

- This is an academic LAN prototype, not an internet-facing embedded product.
- The demo does not include production security hardening, authentication, NAT traversal, TLS, a custom kernel driver, or real-time safety certification.
- `create_linux_system.sh` can overwrite removable media when used incorrectly. Review the target device carefully before running any SD-card write command.
- `devmem` writes are used because the project goal is a transparent HPS-to-FPGA bridge demonstration.
- The preserved Terasic reference material is useful for board setup, but the project-specific evidence is the six-HEX PIO path, HPS Linux write path, TCP wrapper flow and visible board output.

## FAQ

### Is this folder a standalone desktop program?

No. It is the board-side Quartus, Platform Designer, HPS Linux and SD-card project tree for the DE10-Standard board.

### Why does the project use `devmem`?

`devmem` provides a direct, inspectable way to write Lightweight HPS-to-FPGA bridge addresses during an academic prototype. It avoids hiding the main concept behind a custom driver.

### Which file proves the FPGA output wiring?

Use `hw/hdl/project.vhd`. The relevant evidence is the connection from `pio_hex0_external_export` through `pio_hex5_external_export` to `HEX0` through `HEX5`.

### Which file proves the HPS-to-FPGA register path?

Use `hw/quartus/soc_system.qsys` for the Platform Designer bridge connections and `sw/hps/hex_text.sh` for direct register writes.

### Which files prove the public TCP demo?

Use the repository-level `DoAn/s1.cpp`, `DoAn/s2.cpp`, `DoAn/s3.cpp`, and `DoAn/pc_hex_tcp_pink_gui.py` files. They show the generated board-side Python server and the PC client used for LAN testing.

## Review Standard
